# Ping VTuber

CodeMask episode 3: a VTuber made with AI. The character is Ping, an original terminal-face character based on the
channel logo. These rules hold for the whole project.

## Rules

1. **No Live2D, no VTuber apps or their SDKs.** Not VTube Studio, VRoid, Cubism, Warudo or anything similar.
   Animation uses HyperFrames, rig and tracking code are written here.
2. **Every character image comes from the image generator.** Never draw replacement art in code and never retouch
   by hand. Every automatic processing step (crop, background removal, resize, alignment) is done by a script in this
   repository and logged (`art/process-log.json`). Failures are reported and fixed by rerunning the generator with a
   corrected prompt, never by editing pixels.
3. **Disclosure**, per attempt, in `art/generations.json` (and from there `art/SOURCES.json`): Codex CLI version, the
   Codex model of the session, the image tool's name, the image model only if something actually reports it
   (otherwise "not reported"), our prompt id, the prompt as sent, the date, the attempt number, the output pixel size.
4. **Camera rule** (for later steps, written down now): webcam pixels are never drawn to the page, never saved, never
   sent anywhere. This will be enforced by code and by a test.
5. **Determinism.** No `Math.random` and no wall-clock time in anything that affects output. Use the seeded generator
   in `lib/rng.mjs`. Same input gives the same bytes. Avoid `Math.pow`, `Math.exp`, `Math.sin` and similar in output
   code: their last bits may differ between engines; `+ - * /`, `Math.sqrt` and `Math.round` are exact.
6. **Numbers.** Only measured ones, each with the command that produced it. Never estimate, never round in the logs.
   Thresholds in `art/layers.json` are chosen limits, not measurements, and are labelled as such.
7. **PROMPTS.md** holds every prompt the author sends, verbatim and numbered, plus every generator prompt, marked
   `[GENERATOR]`. Generator prompts in PROMPTS.md must match `art/GENERATOR_PROMPTS.md` exactly (a test checks this).
8. **DEVLOG.md**: what was done, what broke, and the real numbers.
9. **Anonymity.** Commits authored as CodeMask, with UTC dates, never the global git identity:
   `TZ=UTC git -c user.name=CodeMask -c user.email=codemask@codemask.invalid commit …`
   (prompt #26). The e-mail maps to no GitHub user: `.invalid` is a reserved domain (RFC 2606), so no account can
   ever verify it, and GitHub shows such commits under the name CodeMask with no profile link. Commits up to and
   including 73feeaa keep codemask@users.noreply.github.com (their hashes are in the video and in FACTS.md: never
   rewrite them); GitHub links those to the GitHub user `codemask`.
   No local paths, no usernames, no `.DS_Store`, no personal data in any file (a test checks tracked files and
   commit authors).
10. **All repository text in English.**

## Generator (Codex CLI, built-in image tool)

- Images are generated by Claude through Codex CLI signed in with ChatGPT, with its built-in image tool. Not the
  Codex plugin for Claude Code (it passes text only). No API key.
- One script makes every call: `npm run generate -- G<n>` (`scripts/generate.mjs`). It runs the `codex` binary
  itself (never the shell alias), `codex exec --json --sandbox read-only`, a fresh session per call, the input image
  attached with `-i`: the logo for G1, `art/raw/01-master.png` for G2 to G8.
- The task is the fixed wrapper in `lib/attempts.mjs` plus the generator prompt from `art/GENERATOR_PROMPTS.md`,
  byte for byte. The wrapper tells Codex to call its image tool once, pass the prompt unchanged, change nothing in
  the result and write no files in the repository. PROMPTS.md logs the wrapper (a test checks it matches).
- The raw event log and Codex's session file are kept in `logs/` and never committed: they hold local paths and
  account details. `npm run attempt:extract` writes the committed extract `art/attempts/<id>.json` with those
  removed, and records what Codex really passed to the image tool against our prompt: identical, or the exact
  difference, or "not reported". Never guess.
- The generated file is copied out of Codex's folder unmodified into `art/raw/attempts/<prompt>-<nn>.png`, with its
  sha256 at the source and at the copy.
- Claude never chooses between attempts and never promotes one to `art/raw/`: the author does. At most 2 attempts
  per prompt without asking the author (`--allow-more` only after they said so).
- An attempt whose pixel size differs from the master's is a failed attempt, kept and logged.

## Workflow

- Node 22 or newer (`.nvmrc` pins 24.15.0; byte-for-byte output is only promised on that version, since PNG
  compression comes from Node's zlib). `npm test` runs everything.
- Raw generator files are never committed before the author has seen their embedded metadata (`npm run metadata`)
  and approved them (`metadataApproved` in `art/generations.json`; a test checks it).
- The canvas is the master's own pixel size; nothing is resampled, and a raw of another size is a failed generation.
- Regions and pivots are measured on the approved master by `npm run regions` with the rules in `art/layers.json`,
  never tuned by hand, and frozen once the author approves the master.
- Offset, drift and screen-size limits stay `null` (measured only) until they are chosen after looking at the first
  real run; DEVLOG says so when they are set.
- Test fixtures are made by code, live only under `test/fixtures/`, are labelled `TEST FIXTURE` in the pixels and in
  a PNG text chunk, and the scripts refuse to use them as character art.
- Do not push and do not add a remote unless the author asks.
