## Prompt #1

```text
You are building the project for CodeMask episode 3: a VTuber made with AI.
The character is Ping, an original terminal-face character based on the
channel logo. This prompt covers setup and step 1 (Ping's layers) only.
Do not build the rig, animation, lip sync or webcam tracking yet.

## Pipeline (fixed)
- Character art: a text-to-image generator, run by me by hand. You write the
  generator prompts; I generate the images and put them in art/raw/.
- Animation (later steps): HyperFrames, the same approach as the CodeMask
  host avatar. Find how the host avatar's layers are organised in the
  CodeMask repo (ask me for the path if you can't find it), mirror its
  conventions for file naming and canvas size where they fit, and report
  what you found and which HyperFrames version it uses.
- Code: written by you.

## Part A: repository and rules
Create a new local git repository `ping-vtuber`. Do not push and do not
create a remote. Add:

1. CLAUDE.md with these rules, to hold for the whole project:
   - No Live2D, no VTuber apps or their SDKs (VTube Studio, VRoid, Cubism,
     Warudo and similar).
   - Every character image comes from the image generator. Never draw
     replacement art in code and never retouch by hand. Every automatic
     processing step (crop, background removal, resize) is done by a script
     in the repo and logged.
   - Disclosure: for every image, record the generator name and version as
     shown in its UI, the date, and the exact prompt.
   - Camera rule (for later steps, written down now): webcam pixels are
     never drawn to the page, never saved, never sent anywhere. This will
     be enforced by code and by a test.
   - Determinism: no Math.random and no wall-clock time in anything that
     affects output. Use a seeded generator. Same input gives the same
     bytes.
   - Numbers: only measured ones, with the command that produced them.
     Never estimate, never round in the logs.
   - PROMPTS.md: every prompt I send you, verbatim and numbered, plus every
     generator prompt, marked as such.
   - DEVLOG.md: what you did, what broke, and the real numbers.
   - Anonymity: commits authored as CodeMask (copy the identity from the
     bug-driver repo, never the global git config), TZ=UTC for every
     commit, no local paths, no usernames, no .DS_Store, no personal data.
   - All repository text in English.
2. PROMPTS.md (this prompt is #1), DEVLOG.md, a short README, .gitignore.

## Part B: layer spec and generator prompts
1. Write art/layers.json: canvas size, and for each layer its id, file
   name, the region of the canvas it may occupy, its parent layer, and its
   pivot point. Layers:
   - head: the screen-face with no eyes, brows or mouth
   - eyes_open, eyes_closed
   - brows (neutral)
   - mouths: propose a set of at most 6 shapes for English speech and
     justify each one in a line. Starting point: rest (also M/B/P), small
     open, wide open, round (O/U/W), wide (E/I), F/V. Drop any you can't
     justify for a face this simple.
   - glow
2. Write the generator prompts in art/GENERATOR_PROMPTS.md, in the order I
   should run them. Method: first one master image of Ping from the
   reference logo (I will add art/reference/logo-5A.png), then every
   variant as an edit of that master in the same chat, changing one
   feature at a time, on a fixed canvas, same framing. State the exact
   file name I should save each result under.
3. Style constraints for the prompts: original character, not a known
   character and not a real person; neon on dark, simple shapes; must stay
   readable at 64 px.

## Part C: processing and checks (build now, on test fixtures)
1. A script that turns art/raw/ into art/layers/: isolates each feature
   into its own transparent PNG on the full canvas. Deterministic.
2. `npm run check:layers` that prints a table for every layer: canvas
   size, alpha bounding box, whether the box is inside its allowed region,
   corner alpha, and for each variant its offset and its colour difference
   from the master outside the changed feature. This table is how we
   measure style drift between generations.
3. A script that writes out/contact-sheet.png: every layer on a
   checkerboard, plus composites of head + eyes_open + each mouth.
4. art/SOURCES.json: sha256 of every raw and processed file, with
   generator, date and prompt id.
5. Tests for the manifest and the checks. Test fixtures are generated by
   code, live only under test/fixtures/, are visibly labelled as fixtures,
   and are never used as character art.
6. Pin dependency versions and keep them few.

## STOP here
Commit and send me the report below. Do not generate, download or draw any
character image yourself. Wait until I say the images are in art/raw/.

## Part D: after I add the images
1. Before committing any raw file, dump its embedded metadata (EXIF, XMP,
   C2PA) and show it to me. Do not commit raw files until I approve.
2. Run the processing, check:layers and the contact sheet.
3. Do not fix failures by editing images. Report them. If a layer fails,
   write the corrected generator prompt for me to rerun.
4. Log every failure and every rerun in DEVLOG.md with the numbers.

## Report format (after the STOP, and again after Part D)
- File tree and commit hashes
- What you found in the CodeMask repo about the host avatar's layers
- The proposed mouth set with reasons
- The generator prompts in full
- Output of npm test and check:layers, pasted as is
- What broke
- Questions for me
```
